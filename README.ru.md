# Kagami API

[English](README.md) | **Русский**

> 鏡 *(kagami — «зеркало»)* — self-hosted зеркало данных MyAnimeList.

Собственный REST API для [MyAnimeList](https://myanimelist.net) на Node.js, совместимый с Jikan. Kagami парсит страницы MAL напрямую — без зависимости от api.jikan.moe — и кэширует каждый ответ в локальной SQLite-базе, поэтому твоё приложение продолжает работать, даже когда MAL тормозит, режет запросы или лежит.

**Почему не просто Jikan?** Jikan — отличный проект, но это общий публичный сервис: тысячи приложений ходят в MAL через одни и те же серверы, MAL блокирует их IP, и ты получаешь `504 — Jikan failed to connect to MyAnimeList`. Kagami работает на *твоём* сервере, с *твоим* IP и *твоим* кэшем. Закэшированные ответы отдаются мгновенно, а если MAL недоступен — вернётся последняя сохранённая копия вместо ошибки.

## Возможности

- **Ответы в формате Jikan v4** — drop-in замена, тот же формат `{ "data": ... }`. Достаточно поменять адрес API в существующем коде.
- **Прямой парсинг MAL** — селекторы портированы из открытого кода Jikan, никаких сторонних API между тобой и MAL.
- **SQLite-кэш с TTL на каждый эндпоинт** — 7 дней для статичных данных, меньше для сезонов и поиска. Сервер БД не нужен.
- **Stale-on-error** — если MAL лежит, а кэш протух, отдаётся устаревшая копия вместо 5xx.
- **Слияние запросов** — параллельные одинаковые запросы порождают один поход в MAL.
- **Список разрешённых сайтов (CORS)** — API отвечает только твоим сайтам.
- **Расширяемость по дизайну** — один файл в `src/api/` = один набор эндпоинтов, подхватывается автоматически.

## Быстрый старт

```bash
npm install
npm start          # http://localhost:3000
```

Требуется Node.js 18+ (на Node 22.5+ используется встроенный `node:sqlite`, на более старых — `better-sqlite3`).

## Эндпоинты

> **Важно:** это не полный порт REST API Jikan v4. Реализованы только эндпоинты, которые нужны проекту [Tunime](https://an0ncer.github.io/). Архитектура позволяет легко добавлять новые — см. раздел [Как добавить эндпоинт](#как-добавить-эндпоинт).

| Эндпоинт | TTL кэша |
| --- | --- |
| `GET /v4/anime?q=...` — поиск (q, page, limit, type, status, rating, score, genres, genres_exclude, producers, start_date, end_date, order_by, sort, sfw, letter) | 1 день |
| `GET /v4/anime/{id}/full` | 7 дней |
| `GET /v4/anime/{id}/pictures` | 7 дней |
| `GET /v4/anime/{id}/characters` | 7 дней |
| `GET /v4/characters/{id}/full` | 7 дней |
| `GET /v4/characters/{id}/pictures` | 7 дней |
| `GET /v4/producers` (q, page, limit; каталог: order_by, sort, founded_from, founded_to, adult, sfw, role) | 7 дней (список) / индекс студий |
| `GET /v4/producers/{id}` | 7 дней |
| `GET /v4/producers/{id}/full` (sfw) — страница студии: цифры, жанры, годы, лучшие тайтлы, признак 18+ | 1 день |
| `GET /v4/producers/{id}/anime` (role, type, q, order_by, sort, status, sfw, page, limit) — тайтлы студии | 1 день |
| `GET /v4/producers/{id}/similar` (limit) — похожие студии по жанрам | индекс студий |
| `GET /v4/recommendations/anime` (page) | 6 часов |
| `GET /v4/seasons` | 7 дней |
| `GET /v4/seasons/now` (filter, sfw, continuing, page, limit) | 6 часов |
| `GET /v4/seasons/{year}/{season}` (filter, sfw, continuing, page, limit) | 7 дней |

Каждый ответ содержит заголовок `X-Cache`: `HIT` / `MISS` / `UPDATED` / `STALE`.

## Студии

Всё о студии берётся с одной страницы MAL (`/anime/producer/{id}`), на которой перечислены все её тайтлы. Kagami разбирает её один раз, кэширует результат, а цифры считает при каждом запросе.

- **`/producers/{id}/full`** — названия, дата основания (с `established_precision`: `day` / `month` / `year`), избранное, ссылки, `stats` (число тайтлов по ролям и форматам, средняя оценка по тайтлам с оценкой, участники, годы работы, анонсы), `genres`, пятилетки `decades`, `top_titles`, `best_rated` и блок `adult`.
- **`/producers/{id}/anime`** — тайтлы студии. `role`: `studio` (по умолчанию), `producer`, `licensor` или `all`; если у компании нет тайтлов роли `studio`, по умолчанию используется `all`, а `meta.role` показывает, какая роль применена. `order_by`: `members` (по умолчанию), `score`, `start_date`, `title`. `status=upcoming` — тайтлы без оценки и с датой выхода впереди.
- **Лимит:** MAL показывает не более 1000 тайтлов на студию; у таких студий `stats.truncated` равен `true`.

### Студии 18+

Студия определяется по доле тайтлов с жанром **Hentai** (id 12) среди всех её тайтлов, любой роли:

| `adult.level` | Доля | `is_adult_studio` |
| --- | --- | --- |
| `none` | 0 | `false` |
| `partial` | меньше 50% | `false` |
| `mostly` | от 50% | `true` |
| `exclusive` | от 90% | `true` |

Пороги настраиваются (`ADULT_SHARE_MOSTLY`, `ADULT_SHARE_EXCLUSIVE`). Блок `adult` (а также `hentai_share_members`, `hentai_share_recent`, `low_sample`) возвращается всегда и считается по полному списку тайтлов; без запроса ничего не скрывается:

- `sfw=true` убирает тайтлы 18+ (`adult: true` в карточке тайтла) из списков, цифр и топов, а студии 18+ — из каталога и из «похожих».
- `GET /producers?adult=only` — только студии 18+, `adult=exclude` — ни одной; `adult=only` главнее `sfw`.
- Похожие студии у студии 18+ — только студии 18+, и наоборот.

### Каталог студий и индекс

`GET /v4/producers` с любым из параметров `order_by` (`members`, `titles`, `favorites`, `score`, `established`, `name`), `sort`, `founded_from`, `founded_to`, `adult`, `sfw` или `role` отвечает из локального **индекса студий**: одна компактная запись на студию, у которой не меньше `INDEX_MIN_TITLES` (10) тайтлов. Без этих параметров приходит обычный список MAL, в который для студий из индекса добавлены цифры.

В каталоге только студии (`is_studio: true`: у компании есть тайтлы с ролью `studio`; студии 18+, у которых MAL указывает роль `producer`, тоже считаются). Лицензиары, телеканалы и прочие продюсеры по умолчанию скрыты; `role=all` добавляет их после студий.

Индекс наполняется и обновляется фоновой задачей: она заходит на страницы студий по одной с паузой (`INDEX_DELAY_MS`), поэтому не нагружает небольшой сервер. Студия обновляется, если:

- её ещё нет в индексе;
- изменилось число тайтлов в общем списке студий MAL (список проверяется раз в сутки);
- она участвует в текущем сезоне (раз в 2 дня);
- пришёл срок: самые востребованные студии (топ `INDEX_HOT_COUNT`) — раз в сутки, остальные — раз в неделю.

**Самые востребованные студии обновляются первыми.** Каждый запрос к эндпоинтам студии засчитывается как обращение; обращения затухают с периодом полураспада `HITS_HALF_LIFE_DAYS` (7), поэтому важнее недавний интерес. Очередь обновления упорядочена по этой величине. Обращения пишутся в SQLite пачками раз в минуту. Фоновую задачу можно выключить: `INDEXER_ENABLED=false`.

## Настройка

Все настройки — через переменные окружения:

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `PORT` | `3000` | Порт сервера |
| `CACHE_TTL_MS` | `604800000` (7 дней) | TTL кэша по умолчанию |
| `DB_PATH` | `data/cache.db` | Путь к SQLite-базе |
| `ALLOWED_ORIGINS` | `https://an0ncer.github.io` | Разрешённые сайты, через запятую |
| `STRICT_ORIGIN` | `false` | `true` — блокировать и запросы без заголовка `Origin` (curl и т.п.) |
| `REQUEST_TIMEOUT_MS` | `15000` | Таймаут запросов к MAL |
| `ADULT_SHARE_MOSTLY` | `0.5` | Доля хентая, с которой студия считается «в основном» 18+ (`mostly`) |
| `ADULT_SHARE_EXCLUSIVE` | `0.9` | Доля хентая, с которой студия считается целиком 18+ (`exclusive`) |
| `INDEXER_ENABLED` | `true` | Запускать фоновое обновление индекса студий |
| `INDEX_MIN_TITLES` | `10` | Минимум тайтлов, чтобы студия попала в индекс |
| `INDEX_DELAY_MS` | `2000` | Пауза между запросами страниц студий к MAL |
| `INDEX_CYCLE_MS` | `21600000` (6 ч) | Как часто собирается очередь обновления |
| `INDEX_LIST_CHECK_MS` | `86400000` (1 день) | Как часто общий список студий MAL скачивается заново для сверки числа тайтлов |
| `INDEX_HOT_COUNT` | `50` | Сколько самых востребованных студий обновляется чаще |
| `INDEX_HOT_TTL_MS` | `86400000` (1 день) | Период обновления этих студий |
| `INDEX_SEASON_TTL_MS` | `172800000` (2 дня) | Период обновления студий текущего сезона |
| `INDEX_COLD_TTL_MS` | `604800000` (7 дней) | Период обновления остальных студий |
| `INDEX_MAX_FAILS` | `3` | Сколько ошибок MAL подряд останавливают проход обновления |
| `INDEX_LOG_EVERY` | `10` | Как часто (в студиях) писать в лог прогресс прохода |
| `HITS_HALF_LIFE_DAYS` | `7` | Период полураспада счётчика обращений, по которому выбирается приоритет обновления |

## Доступ (CORS)

API отвечает только сайтам из списка разрешённых. Запросы с чужих сайтов получают `403` в формате Jikan. Запросы без заголовка `Origin` (curl, адресная строка) по умолчанию разрешены — чтобы удобно тестировать; заблокировать их можно через `STRICT_ORIGIN=true`. Origin с `localhost` разрешён всегда — для локальной разработки фронтенда.

## Кэширование

Ответы хранятся в SQLite (`data/cache.db`, создаётся автоматически). Когда запись протухает, она обновляется при следующем запросе. Если обновление не удалось (MAL лежит или блокирует), отдаётся устаревшая копия с `X-Cache: STALE` — пользователи никогда не увидят знаменитый 504 Jikan.

## Как добавить эндпоинт

Каждый эндпоинт — отдельный файл в **`src/api/`**, сервер подхватывает все `.js`-файлы при старте. Файл экспортирует функцию, принимающую роутер `/v4`:

```js
// src/api/manga.js
const { cached } = require('../cache');
const { fetchPage } = require('../mal/client');

module.exports = function register(v4) {
  v4.get('/manga/:id/full', async (req, res, next) => {
    try {
      const { data, cache } = await cached(`manga/${req.params.id}/full`, async () => {
        const html = await fetchPage(`/manga/${req.params.id}`);
        return parseMangaFull(html); // свой парсер в src/parsers/
      });
      res.set('X-Cache', cache);
      res.json({ data });
    } catch (e) { next(e); }
  });
};
```

HTML-парсеры лежат в `src/parsers/` (селекторы можно портировать из [исходников Jikan](https://github.com/jikan-me/jikan/tree/master/src/Parser)).

## Структура проекта

```
src/
  server.js        — Express, автозагрузка эндпоинтов из src/api, CORS
  config.js        — порт, TTL, путь к БД, разрешённые сайты (через env)
  db.js            — SQLite (node:sqlite или better-sqlite3)
  cache.js         — TTL-кэш + stale-on-error + слияние запросов
  errors.js        — ошибки в формате Jikan
  api/             — ПАПКА РАСШИРЕНИЯ: один файл = один набор эндпоинтов
  lib/             — цифры студий и определение 18+, списки тайтлов, индекс студий, фоновое обновление, счётчик обращений
  mal/
    client.js      — загрузка HTML с myanimelist.net
    utils.js       — общие хелперы парсинга (картинки, id, чистка текста)
  parsers/         — HTML страниц MAL -> JSON в формате Jikan v4
test/              — тесты парсеров на фикстурах, логики кэша, цифр/индекса/роутов студий (на локальной имитации MAL)
```

## Совет по развёртыванию

Kagami отлично живёт на маленьком домашнем сервере за [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/) — домашний IP MAL блокирует куда реже, чем IP датацентров (а это и есть первопричина 504 у Jikan).

## Дисклеймер

Kagami API — неофициальный проект, **не аффилирован с MyAnimeList**. Все данные принадлежат их владельцам. Используй ответственно: встроенный кэш существует для того, чтобы трафик на MAL был минимальным.
